Introduction

1.1

Purpose of the Document

Fall 2025

This Software Design Document (SDD) defines the architectural and detailed design of
the Clinexa Medical System based on the Software Requirements Specification (SRS).
The document serves as a comprehensive blueprint that translates functional and nonfunctional requirements into a structured design that can be implemented by the development team.
The SDD provides:
• A clear explanation of the system’s architectural structure and design patterns
• Detailed descriptions of system components and their interactions
• Visual representations through UML diagrams and UI mockups
• Data storage design and file structure specifications
• Technology stack and implementation guidelines

1.2

Scope of the Design Phase

This design document covers the complete system design for the Clinexa Medical System,
including:
• Architectural Design: High-level system architecture using a monolithic architectural style, component identification, and interaction patterns.
• Design Patterns: Implementation of the Model-View-Controller (MVC) design
pattern.
• Module Design: Detailed design of User Management, Authentication, Patient
Management, Doctor Management, Appointment Management, Medical Records,
Notifications, Reports, and Search functionality.
• Data Storage Design: File-based data storage structure using text files.
• User Interface Design: Wireframes and mockups for key user interfaces.

System Overview

2.1

Brief Description of the System

Fall 2025

Clinexa is a web-based healthcare management system designed to streamline interaction
between healthcare providers and patients. The platform replaces traditional paper-based
processes with a digital solution accessible through web browsers.
Patients can create accounts, search for doctors by specialization, book appointments,
view medical history, receive automated email reminders, and submit feedback. Doctors
can manage availability schedules, view appointments, access patient histories, create
medical records, generate reports, and respond to feedback.

2.2

Key Design Goals and Constraints

2.2.1

Design Goals

• Usability: Intuitive interface requiring minimal training, accessible through modern web browsers.
• Efficiency: Streamlined processes for appointment scheduling and medical record
retrieval.
• Reliability: 99.9% uptime with recovery time under 5 minutes.
• Maintainability: Modular design with clear separation of concerns through MVC
pattern.
• Security: Robust authentication with password hashing and role-based access
control.
2.2.2

Constraints

• Technology Stack: Flask backend, HTML/CSS frontend, file-based storage, UML
2.5 notation.
• Operating Environment: Chrome and Firefox browsers, cloud server hosting.
• External Dependencies: Email gateway API for notifications.

Model–View–Controller (MVC) Design Pattern

4.1.1

Description of MVC Pattern

Fall 2025

The Model-View-Controller (MVC) is an architectural design pattern that separates an
application into three interconnected components.
Components:
• Model: Data layer and business logic
• View: User interface presentation
• Controller: Request handling and flow control
Why MVC Was Chosen:
1. Separation of concerns for maintainability
2. Enables parallel development
3. Improves testability
4. Framework compatibility with Flask
5. Supports future scalability

4.4.1

File Structure / Data Storage Model

Fall 2025

The Clinexa system uses nine text files for data storage in the clinexa data/ directory:
clinexa_data/
users.txt
patients.txt
doctors.txt
appointments.txt
medical_records.txt
notifications.txt
authentication_logs.txt
feedback.txt
reports.txt
Data Format Conventions:
• Primary Separator: Pipe (—) separates fields
• List Separator: Semicolon (;) for multiple items
• Key-Value Separator: Tilde (˜) for structured data
• Encoding: UTF-8
• Null Values: ”NULL” or ”None”
